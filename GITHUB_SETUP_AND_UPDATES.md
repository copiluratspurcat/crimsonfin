# CrimsonFin v0.6 — Windows, Debian 13 and automatic updates

Configured GitHub repository: **copiluratspurcat/crimsonfin**. **You must create this public repository on GitHub first**. Merely having a GitHub account does not create it.

## Initial upload from Debian 13

1. Create a new **public**, **empty** repository named `crimsonfin` in the GitHub web interface. Do not initialize it with a README, .gitignore or license.
2. Extract this ZIP; open Konsole inside the extracted `CrimsonFin-v0.6-GitHub-Windows-Linux` folder.
3. Run:

```bash
git init
git branch -M main
git add .
git commit -m "CrimsonFin v0.6: Windows/Linux release pipeline"
git remote add origin https://github.com/copiluratspurcat/crimsonfin.git
git push -u origin main
```

GitHub HTTPS git push requires authentication via a personal access token or credential manager; your GitHub account password cannot be used for git push. If `git` is missing: `sudo apt install git`.

## Build Windows EXE, Linux DEB and AppImage on GitHub

Under repository **Settings → Actions → General → Workflow permissions**, select **Read and write permissions** and save. This is needed to publish release assets using the built-in `GITHUB_TOKEN`.

Create a version tag and push it:

```bash
git tag v0.6.0
git push origin v0.6.0
```

Open GitHub → your repository → **Actions**. The workflow `Build Windows and Linux installers + publish update feeds` compiles both platforms on GitHub-hosted Windows and Linux runners. On success the **Releases** section contains:

- `CrimsonFin-Setup-0.6.0.exe` (Windows installer, x64)
- `CrimsonFin-0.6.0-Linux-x64.deb` (Debian package, x64)
- `CrimsonFin-0.6.0-Linux-x64.AppImage` (portable Linux package, x64)
- `latest.yml`, `latest-linux.yml`, and Windows `.blockmap` files (auto-update metadata; do not delete them)

**These binaries are generated by GitHub Actions; they are not contained in this source ZIP.** This release workflow has not been run/tested against your repository yet.

## Installing

- **Windows:** download and run the EXE from your GitHub Release. Windows SmartScreen may warn about the installer until it is signed and has established reputation. Do not bypass security prompts for untrusted installers.
- **Debian 13:** download the `.deb` and run `sudo apt install ./CrimsonFin-0.6.0-Linux-x64.deb` from its download directory.
- **Linux AppImage:** `chmod +x CrimsonFin-0.6.0-Linux-x64.AppImage` and launch it. Depending on the distro, FUSE 2 compatibility may be required. AppImage is the option with built-in application updates.

## When creating v0.7.0 (and each future version)

1. Edit the code locally in the project folder.
2. Update `package.json` `version` from `0.6.0` to `0.7.0` (or run `npm version 0.7.0 --no-git-tag-version`).
3. `git add . && git commit -m "Release 0.7.0" && git push`
4. `git tag v0.7.0 && git push origin v0.7.0`
5. Wait for the `Actions` workflow to succeed. It publishes the new EXE, DEB, AppImage, and update manifests under the new GitHub Release.

On application startup and every 6 hours, **installed Windows NSIS** and **Linux AppImage** builds check for newer stable GitHub releases. They automatically download available updates; when ready, CrimsonFin offers **Restart & install**. The `.deb` variant is **not auto-updated** and must be replaced using a newer `.deb` (or a future APT repository).

For AppImage auto-updates, start the actual `.AppImage`, not `npm start` or the `.deb` installation. The installed Windows variant must also originate from a published GitHub installer with `app-update.yml` included.

**Version tags must match the version in package.json.** Both the public GitHub release and the assets/manifest files must be present for auto-updates to work. Avoid prerelease/draft releases for stable updates.

## Troubleshooting

- If Windows/Linux jobs fail, inspect Actions job logs. The project has not been compiled here due to the environment lacking access to npm registry and Electron downloads.
- If a release is missing assets, use the Actions artifacts for debugging, fix the underlying build, then delete and recreate the failed release/tag as appropriate; don't claim updates are working until both manifest files are uploaded.
- Electron/NSIS installer is currently **unsigned**. Signing is strongly recommended before wide distribution. Building a file does not verify its safety, quality, or operating-system compatibility.
- GitHub does not automatically update source files: **you** must commit/push changed source and tag new versions. The release build/publishing is automated after you push the tag.
