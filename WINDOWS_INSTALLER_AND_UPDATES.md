# CrimsonFin Windows installer and auto-updates

## What is included

CrimsonFin v0.5 includes an NSIS `.exe` installer configuration, a GitHub Actions Windows build workflow, and an in-app Windows update client. **The source ZIP is not itself an `.exe` installer.** An installer is generated by the GitHub workflow or locally on Windows. Auto-updates only work after you configure a public GitHub repository, publish a release, and install the NSIS `.exe` (not `npm start`).

## First time (one-time setup)

1. Create a **public** GitHub repository (for example `YOURNAME/crimsonfin`).
2. In the source folder run `npm run configure:updates -- YOURNAME/crimsonfin` (Node.js required). This modifies `package.json` to set the release feed; commit that modified file.
3. Upload/push the **contents of this folder**, including the `.github/workflows/release-windows.yml` workflow, to the repository. Ensure GitHub Actions are enabled and **Settings > Actions > General > Workflow permissions > Read and write permissions** if your repository requires it. The workflow uses `GITHUB_TOKEN`, not a personal token.
4. Set version in `package.json` to `0.5.0`, commit and push. Then tag: `git tag v0.5.0` and `git push origin v0.5.0`.
5. GitHub Actions will build the Windows installer and publish a release with `CrimsonFin-Setup-0.5.0.exe`, `latest.yml` and any generated blockmaps. If a draft release is created, publish it; auto-updater ignores drafts.
6. Download the installer from GitHub Releases and run it on Windows.

## Releasing an update

1. Edit the app. Increase `version` in `package.json`, e.g. `0.5.1`.
2. Commit and push changes. Tag that same version with `git tag v0.5.1 && git push origin v0.5.1`.
3. GitHub Actions publishes the new Windows installer and update metadata. **Once the release is public**, installed Windows clients check on launch and every six hours, download automatically, and offer **Restart & install**.

## Building on Windows without GitHub

Install Node.js 22 and run `npm install`, then `npm run pack:win`; find the `.exe` in `release/`. This is a local installer, but automatic updates will not be available until a release feed is configured and releases are published.

## Limitations

- This package does not include a prebuilt executable because the current environment cannot download required Electron dependencies or run a verified Windows build.
- Windows installer is unsigned by default and may show a SmartScreen warning. For distribution to others, use trusted code signing; don't ask people to bypass warnings without verifying the source.
- Only the **NSIS installer** auto-updates; portable builds and Debian `.deb` installations are not set up for auto-update. Linux users can continue to update manually.
- Public GitHub releases are required for the simple setup provided here. A private repository needs a different authenticated update approach.
- Publish each tag after its assets and `latest.yml` are present. Avoid releasing a newer version before its installer metadata exists.
